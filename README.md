# 手持商品 MVP · Handheld Product MVP

> 千图AI 商品图功能的垂直增强 — 对标万相营造的"手持商品图"功能,以最小 MVP 快速验证电商用户对此场景的真实需求。

---

## 项目身份

- **对标产品**:万相营造(阿里通义) — 手持商品图功能
- **本项目目标**:在千图AI 现有商品图功能里加一个"手持版"入口,验证电商用户对此场景的真实需求
- **本项目不是什么**:不是设计系统(那是 design 项目本身的事);不是公司主仓代码(MVP 真正代码会在千图AI 前端单仓拉 feature branch)
- **为啥放在 design 目录下**:作为产品文档暂存。代码不在这里,代码在公司主仓 `feature/handheld-product-mvp` 分支

---

## 关键决策(已敲定)

### MVP 范围(已砍到最小)

| 维度 | 范围 |
|---|---|
| 模特数 | 3 个 stock 模特(免肖像授权) |
| 姿势 | 1 个固定姿势 |
| 算法 | 复用千图AI 现有 AI 算法服务 + 新底模 |
| 入口 | 千图AI 商品图功能页 tab(显眼位置,不藏菜单) |
| 计费 | 复用现有算力体系 |
| 周期 | 3 周开发 + 4 周观察 |

### 成功标准(行为指标,不算钱)

| 指标 | 算法 | 阈值(达不到=砍) |
|---|---|---|
| 使用率 | 点过该功能的电商用户 / 电商总用户 | ≥10% |
| 完成率 | 完成生成 / 点过 | ≥30% |
| 复用率 | 7 天内 ≥2 次 / 用过 1 次 | ≥15% |

**决策规则**:跑 4 周看结果
- 3 指标全过 → 投入做完整版(扩姿势、加参照物、扩模特库)
- 1-2 个过 → 优化后再观察 2 周
- 全不过 → 砍,知识沉淀走人

## 架构落地(已确认)

- **前端**:千图AI 前端单仓 → feature branch:`feature/handheld-product-mvp`
- **后端**:复用现有 AI 算法服务(部分微服务架构),通过 API 接入
- **不新建独立 repo**:MVP 是现有商品图功能的增量,放主仓 feature branch 上线最快

## 5 个必避陷阱(开局就解决)

| # | 风险 | 解决方案 | 阶段 |
|---|---|---|---|
| 1 | 算法出图质量太差 → 数据失真 | M3 Day1 先跑算法 POC,质量过线再继续工程化 | M3 |
| 2 | 入口埋太深 → 渗透率假阴 | 入口位置在 PRD 写死(商品图页 tab) | M2 |
| 3 | 埋点不全 → 上线后无法判断 | 3 个指标的埋点写进 PRD,工程同步实现 | M2 |
| 4 | 算力计费对接卡 deploy | M2 阶段联系后端确认计费对接 | M2 |
| 5 | 模特素材没人出 → 无法上线 | M3 前确认 stock 来源(采购 / 合成) | M3 |
